## [1.5.0] — 2026-10-22

Major release: correctness overhaul, security hardening, architecture
modernization, detector recalibration, and full documentation.

### Added
- Method-bound AES-GCM encryption (v3 envelope, with legacy fallback) plus optional
  key-derived headers (`--no-magic`) and plaintext padding (`--pad-to`).
- Fail-closed plaintext policy: encoding without a key is refused unless
  explicitly opted in (`--allow-plaintext`, `--key-file` supported).
- Forensic audit trail: `case_id`, `file_sha256`, and versioned JSON reports
  with canonical hashing (`stegoforge_ops.report`).
- Parallel batch encoding (`--jobs`), detector-blend web dashboard,
  machine-readable schemas (`stegoforge schema`, shipped inside the package as
  `stegoforge_ops/schemas/`, and `docs/openapi.yaml`), and a complete man page (`docs/stegoforge.1`).
- New modules: `stegoforge_ops/` (canonical operation layer), `core/bits.py`,
  `core/config.py`, `core/errors.py`, offline model integrity verification.

### Changed
- CLI split into a thin command layer over `stegoforge_ops/`; web UI serves
  opaque artifact IDs, localhost-only CORS, optional token auth, and real
  streamed encode progress.
- DCT encode/decode fully vectorized; blind extractor runs a worker pool;
  video metadata uses a single cached scan.
- `Pillow` is required at `>=13.0.0` on Python 3.11+ (24 published advisories against 12.3.0: decoder out-of-bounds reads and crashes on crafted TIFF/PPM/PDF input). Python 3.10 stays supported but can only get 12.3.0, so the blocking dependency audit now runs on 3.12.
- Dependencies locked for the whole supported range (`requirements.lock`, `requirements.hash.lock`: one universal resolution for Python >= 3.10, regenerated by `scripts/compile_lock.sh`); CI runs lint, typecheck, tests on 3.10 and 3.12, a blocking security audit, SBOM generation, distribution content checks and an apt install of the `.deb`. PyPI publishing is OIDC trusted publishing behind a test gate.

### Fixed
- LSB depth-3/4 tail corruption; empty-payload and out-of-range depth handling;
  ELF/PE bounds errors; corrupted PDF/Office recovery errors; video temp-file
  leaks; palette capacity and duplicate-color mapping.
- **Detector calibration (all thresholds measured, none guessed):**
  audio-anomaly false positives eliminated (1.00 → 0.00 FPR) while keeping
  phase-embed detection at 1.0 confidence; chi-square now catches DCT embeds
  via a dedicated JPEG-branch threshold; `ml`/Chisquare prior double-counting
  removed (ml FPR 0.40 → 0.00).
- Measured on a 20-file corpus (4 clean, 16 stego); see `docs/DETECTOR-EVAL.md`. The numbers are a smoke test, not a benchmark, and RS still flags one clean file.

### Security
- Self-update pins its upstream repository and verifies assets (cosign/SHA256),
  refusing unpinned auto-apply; web uploads are filename-sanitized with
  symlink-safe artifact storage; dead-drop and LLM helpers enforce URL
  allowlists and size caps; key-exchange files are written `0600`.
- Known limitation, documented honestly: the bundled ONNX weights expose an
  ImageNet classifier head rather than a steganalysis head, so the `ml`
  detector runs its heuristic fallback (triage-only) until compatible weights
  ship. See `docs/MODEL-CARD.md`.

### Follow-up hardening (2026-10-22)

**Fixed**
- The CLI/web operation layer had not been ported to the v3 crypto envelope: it fell back to legacy encryption behind a blanket `except`, guessed padding at decode time (dropping real trailing bytes), and its survival check always failed. Embeds are now v3, method-bound, with canonical method labels so aliases (`adaptive`, `office`, ...) decode.
- Decoy containers were unreachable with the decoy key (the traversal key was the real passphrase). They are embedded unkeyed and the decoder tries both traversals.
- `op_batch_encode` failed on every file (`NameError`), re-encoded its own `*_stego` output and let same-named files overwrite each other.
- Video methods never round-tripped. They now embed in the yuv420p luma plane and write lossless H.264, select frames by index, verify their own output, keep audio and timing, and use a stable integer ordering.
- Default output names now carry the format the encoder really produces (`mp3` input to `.wav`, `dct` to `.jpg`).
- `chi2`, `binary` and `video-anomaly` false positives/negatives (see `docs/DETECTOR-EVAL.md`); the ELF parser no longer mistakes live data for padding in binaries rewritten by BOLT (section headers that contradict the program headers, as in uv/python-build-standalone interpreters), and padding made of one repeated non-zero byte is treated as toolchain fill; `guess_payload_ext` no longer labels text starting with `BM`/`MZ` as BMP/EXE.
- `keyx` private-key files written by <= 1.1.5 open again (new files are `SKX3`); `keyx complete` no longer falls back silently to the unbound v1 session key (`--legacy-v1` is explicit); the local passphrase is prompted for instead of living in `argv`.
- Dead-drop `check` leaked a temp file and lost its result in `/tmp`; `post` showed tracebacks.
- Wheel shipped without the ML model; `stegoforge schema` crashed on a pip install; the `.deb` omitted `stegoforge_ops` and could not start; `lxml` was imported but undeclared; three declared requirements were never imported.

**Security**
- Web: anchored CORS (`localhost.evil.com` was accepted), `Host` allow-list against DNS rebinding, `Origin` check on POSTs, constant-time token compare (the generated `auto` token was never honoured), plaintext embeds only on explicit opt-in, no temp paths or exception text in responses, downloads served as attachments, hostile file content escaped in the UI, fonts self-hosted (the page used to call Google Fonts).
- `core/sysmgr.py` no longer downloads, `chmod`s and runs unverified third-party ffmpeg binaries; `--offline` is now enforced.

**Changed**
- Web UI redesigned: a calm darkroom palette with one accent, keyboard-accessible tabs, inline errors instead of `alert()`, a non-blocking progress bar, accurate copy.
- CLI output redesigned: compact aligned summaries, one detector table with an INCONCLUSIVE state, errors on stderr with a hint and a stable `code` in `--json`, shell completion generated from the live command tree (zsh `#compdef` was never on line 1), new `stegoforge doctor`, `stegoforge web --host`.
- `core/video/*`, `detect/{binary,chi2,video_anomaly}.py`, `stegoforge_ops/*`, `web/*` and the packaging were reworked as above; `core/network/` was deliberately not touched.

### Compatibility with 1.1.5 (measured by creating files with the published release and opening them with this one)
- **Opens:** every embed 1.1.5 could produce: `lsb` at depths 1-4, `adaptive-lsb`, `fingerprint-lsb`, `alpha`, `dct`, `audio-lsb`, `unicode`, `pdf`, `docx`, `xlsx`, `elf`, wet-paper, and old decoy containers with the real key; `keyx` private-key files from 1.1.5.
- **Key exchange:** a 1.5 peer talking to a 1.1.5 peer must pass `keyx complete --legacy-v1`, which reproduces 1.1.5's session key exactly (pinned by a vector produced by the 1.1.5 code). Two upgraded peers use the new peer-bound key by default.
- **Not readable, and never were:** 1.1.5 corrupted the last bits of some `--depth 3` embeds (about half of them for one payload length, mostly depending on the encrypted size); 1.1.5 itself cannot open those files either. The decoy key of a 1.1.5 decoy container never worked from the CLI.
- **One-way:** files made by 1.5 (v3 envelope, new decoy layout, `SKX3` key files) cannot be opened by 1.1.5.
- **Measured limits worth knowing:** `dct` plus wet paper survives the simulated recompression of 7 of 10 platform profiles and fails for WhatsApp, Facebook and TikTok (JPEG quality 76-80); `palette` cannot carry an encrypted payload.

### Validation
- 400+ pytest tests pass on Python 3.10 (clean environment from the hashed lock) and 3.14; ruff and mypy are clean (one documented per-file ruff ignore for `core/network/tcp.py`); a Playwright journey (`scripts/ui_smoke.py`) drives encode, download, decode, detect, keyboard navigation and a phone viewport in real Chrome.

## [1.1.0] — 2026-04-17

### 🚀 New CLI Commands

- **`stegoforge diff`** — Compare an original carrier against its stego version.
  Reports changed pixels / differing bytes, plus saves an amplified heatmap PNG
  that visually highlights every modified region.
  ```
  stegoforge diff -c cover.png -s stego.png
  stegoforge diff -c cover.png -s stego.png --save-heatmap heat.png --json
  ```

- **`stegoforge batch`** — Encode a payload into an entire directory of carriers in one command.
  Supported formats: PNG, BMP, TIFF, WEBP, JPG, GIF, WAV, MP3, FLAC, OGG,
  MP4, MKV, AVI, PDF, DOCX, XLSX, TXT. Displays a live Rich table with
  per-file status, method, capacity, and output path.
  ```
  stegoforge batch -d ./images/ -p secret.txt -k mykey
  stegoforge batch -d ./carriers/ -p msg.pdf -k mykey -o ./out/ --depth 2
  ```

- **`stegoforge completion`** — Generate tab-completion scripts for bash, zsh, and fish.
  ```
  eval "$(stegoforge completion bash)"    # add to ~/.bashrc
  eval "$(stegoforge completion zsh)"     # add to ~/.zshrc
  stegoforge completion fish | source
  ```

### ✨ CLI Enhancements

- **Stealth score** added to `stegoforge capacity` output — a composite 0–100 rating
  (weighted by chi-square resistance, RS resistance, ML evasion, and perceptual
  invisibility) shown as a colour bar for each method.
- **Smart capacity-exceeded errors** — when a payload is too large, StegoForge now
  shows the exact gap in bytes, then lists accurate suggestions:
  which `--depth` level would fit the payload, whether `adaptive-lsb` would help,
  and whether compressing the payload first is a viable option.
- **`STEGOFORGE_KEY` environment variable** — both `encode` and `decode` now fall
  back to this env var when `-k / --key` is not provided, so passwords no longer
  need to appear in shell history or CI scripts.
- **Interactive menu** updated with `d` (Diff) and `b` (Batch) entries.

### 🌐 Web UI Enhancements

- **Payload preview in Decode tab** — after successful decoding the payload is
  rendered inline: images show as `<img>`, audio plays via `<audio>`, text
  appears in a scrollable pane. No file-system access needed.
- **Smart download extension** — the Decode and CTF tabs now correctly name the
  downloaded file (e.g. `decoded_payload.png`, `decoded_payload.mp3`) instead of
  always using `.bin`, based on magic-byte detection covering 15 common formats.
- **CTF SFRG blob advisory** — when the blind extractor finds a `SFRG`-magic payload
  (a StegoForge-encrypted blob), the UI shows a clear advisory explaining how to
  decrypt it with the correct key.
- **Key strength meter** — live Shannon-entropy bar under every passphrase input
  (Encode and Decode tabs), scored 0-100 from length, character variety, and entropy.
- **Carrier image preview** — dropping an image carrier in the Encode tab shows
  an immediate thumbnail preview.
- **Mobile hamburger nav** — the header navigation collapses behind a hamburger on
  screens ≤ 600 px wide.
- **Artifact cleanup** — old web temp files (> 1 hour) are cleaned up on startup.

### 🐛 Bug Fixes

- **B1** — Fixed `DeprecationWarning: Image.Image.getdata` in `core/image/palette.py`
  (Pillow 14 compatibility). Uses `numpy.array(img).flatten()` instead.
- **B2** — Replaced hardcoded `/tmp/stegoforge_stdin_*.bin` paths in `cmd_detect`
  and `cmd_ctf` stdin handlers with `tempfile.mkstemp()` for cross-platform safety.
- **B3** — Removed dead code block (unreachable dashboard panel after `return result`
  in `op_update`).
- **B6** — Web artifact temp files (prefixed `stegoforge_web_artifact_`) are now
  automatically deleted on startup if older than 1 hour.

## [1.0.0] — 2026-04-14  *(Initial Public Release)*

### 🎉 First release

StegoForge launched on GitHub and received **41 stars + 13 forks** within 72 hours.

#### Carrier support (20 encoding methods)
| Carrier | Methods |
|---------|---------|
| **Image** | LSB · Adaptive-LSB · Fingerprint-LSB · DCT (JPEG) · Alpha · Palette |
| **Audio** | LSB · Phase · Spectrogram |
| **Video** | DCT · Motion-vector |
| **Document** | Unicode zero-width · PDF · DOCX · XLSX |
| **Binary** | ELF slack · PE slack |
| **Network** | IP-ID · TCP-Seq · TTL · Timing channel |
| **Linguistic** | ML-guided cover-text generation |

#### Detection engines (11 engines)
Chi-square · RS Analysis · EXIF/Metadata · blind brute-force · ML (ONNX) ·
PRNU/Fingerprint · Binary slack · Survival simulator

#### Core features
- AES-256-GCM encryption with Argon2id KDF
- Reed-Solomon wet-paper protection for JPEG social-media survival
- Dual payload (decoy/real) deniability
- X25519 ephemeral key exchange over dead-drop carriers
- Dead-drop protocol: post / check / monitor
- Batch CTF forensic analysis (`--batch`)
- Platform survivability profiles: Twitter, Instagram, Telegram, Discord,
  WhatsApp, Facebook, TikTok, LinkedIn, Reddit, Signal
- Cross-platform binaries (Linux, macOS, Windows) via GitHub Actions
- Web UI: glassmorphism dark theme, SSE streaming, capacity matrix
- Auto-update via GitHub releases
